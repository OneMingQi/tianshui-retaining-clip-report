## 2. 提速从哪里来，以及对我们的价值

| 更新项 | 核对结果 | 对我们建议 |
|---|---|---|
| 观测/策略线程池 | `ThreadPoolExecutor`，默认 `par_workers=1`。包内测速反而显示4/8线程从43.7增至66.9/74.7 ms/步，更慢 | 不优先启用；先量真实热点 |
| IK 进程池 | `ProcessPoolExecutor` + `spawn`，每进程独立 IK 处理器，运行原回退求解逻辑 | 值得参考，但先解决依赖兼容、确认我们的执行器是否存在同一热点 |
| 每步位姿缓存 | 批量查询同一种 USD 变换 API，并在状态修改后失效 | 可减少重复查询；安全观测必须新鲜，物体真值不能进入部署策略 |
| NumPy 近似 IK | `TIANSHUI_IK_POOL=0` 关闭的是原解进程池，转向近似批量求解，不是简单“关闭并行” | 改变运动轨迹，应作为另一个执行器版本验证 |
| GPU 缓冲扩容 | 随环境数增加接触、patch、pair缓冲 | 有助于避免溢出；不能修复接触几何错误 |

## 3. 群聊中最值得学习的控制思路

### 3.1 先把基础控制做稳，再让模型学习

原始数采策略是人工编写的力反馈样例，并非强化学习得到的成熟控制器。其结构是“腕力→末端位置修正→关节驱动”，不能仅凭有刚度/阻尼参数就称为完整六维阻抗控制器。

接触刚度高、每步修正偏大、反馈延迟、指令持续积分，确实可能造成“接触—回弹—失去接触—重新接触”的循环。降低外环增益、限制每步和累计修正、加入适当滤波/阻尼，都有机制依据。不过降低增益也可能延长周期或导致卡住，不能只看力曲线变平。

同事已报告入口振荡减少、插入后段仍有振荡，说明应按阶段看问题。我们应分别统计：入口接触瞬态、插入持续载荷、卸载跟随、开爪位移、完全撤离后的稳定性；不能用一张全程合力图替代归因。

群聊截图没有给出完整A/B数值，无法精确复现他们的调参。包内 `robot_zte24.json` 与我们发布目录完全一致，各型 `entry_kf` 仍为4e-6，因此不能声称此ZIP已包含群聊所述整套降振增益或机器人阻尼调整。

### 3.2 最有价值的流程更新是落座与释放交接

实际配置变化包括：三型增加落座Z容差1.2mm、连续保持8帧；中型增加力导向搜索和释放补偿；小型释放160→320帧、取消3mm边开边抬、限制夹指回退5mm、添加XY固定补偿(7.5,3.5)mm。

这里应借鉴“先到位、再卸载、再释放、最后撤离”的分段和 `handover` 触发原因记录。**固定补偿数值不可直接复制**：我们的最新小型记录已显示释放入口至回撤入口发生负X方向4–7mm实际移动，增加固定偏移缺乏可靠依据。我们也已修复卸载命令未走完的问题，但命令到达尚不等于接触力已卸除。

中型 `grad` 搜索主要沿力方向构造修正，是启发式，不是已测得的目标函数梯度。采用前要核查力坐标系、符号、自重补偿与多接触下的方向含义。

### 3.3 上游仍保留的风险必须避开

1. **圆周搜索累积**：随机入口分支仍把圆周偏置逐帧加进 `_xy_goal`，并非围绕固定中心给绝对位置。我们已经处理过同类问题：1.2mm请求形成9.194mm实际指令峰半径，修复后1.200mm。移植时不能把旧机制带回来。
2. **XY护栏存在兜底绕过**：默认 `seat_xy_tol=0` 不检查XY；即便显式配置8mm门槛，240帧Z到位兜底仍忽略它。复用上游静态stub例子延长运行，XY偏20mm、Z误差0.5mm，在第240次调用进入卸力，触发 `seat_z_only`。这是逻辑诊断，不是实际固定夹脱落实验。
3. **滤波注释与实现不符**：质量统计称“5帧中值”，实际 `np.convolve(...ones/5...)` 是5帧滑动平均。它位于事后 `_quality()`，不是在线反馈。在线Z力环另有 `entry_filt=0.3` 的EMA。不能把事后平滑曲线当成控制降振。
4. **释放命令连续性待查**：固定方向力补偿在力降至阈值以下时未显式清零旧 `_rel_f`，释放帧结束后的hold又不包含该项；可能留下补偿记忆或命令跳变。本次为源码风险判断，未做物理复现。

本机原有控制护栏单测7/7通过；上述240帧扩展诊断揭示了原测试只覆盖前5帧的边界。数值IK3项则因版本接口阻断，不能汇报成“10项测试全部通过”。

依据：U/`controllers.py:645,707,751,909,934,1184,1229`；`configs/envs.json`；`data_generator.py:46`；本目录 `verification.json`。本机最新控制证据：`runs/resumed_20261105/bounded_dither_v1/进展.md`。

包内同模型 `xy_policy_rl8.pt`、seed91、每型10次、8环境的作者报告：

|---|---:|---:|

| 中型lab2 | 2/10 | 3/10 |
| 小型lab3 | 5/10 | 10/10 |
| 合计 | 17/30=56.7% | 23/30=76.7% |

核对两份JSON，30条保存的工况ID、offset及entry_offset完全相同。7例由失败变成功、1例反向变化；把这些记录视为配对样本，精确双侧McNemar/binomial检验p=0.0703，未达到常用0.05门槛。这是有改善信号的开发结果，尚不足以证明稳定统计优势，更不是95%可靠性证据；每型10例也偏少。

几个口径问题尤其需要保留：

- **随机扰动文档矛盾**：DIFF写“Z不扰动”，随包报告写“Z同XY”；两份JSON保存的Z偏置实际从−9.401到+9.972mm，均非零。两版保存元数据相同，但不能把该实验描述为仅XY扰动；元数据相同也不证明物理初态相同。
- **质检通过不等于低抖动**：代码明确只记录抖动，不以抖动作为硬门；当前硬质检主要限制5帧平均合力与单帧峰力。数采接口默认250/500N，评测入口把平均力默认改为350N；报告JSON没有完整保存实际阈值，不能据默认值补写历史实验条件。这一点旧本地发布代码也有，不能说是v2新增放宽。它与我们的45秒综合质量验收不同。
- **25/30=83.3%是另一“落座”标准**：横向≤4mm、Z距该任务本批次结果中位数≤0.6mm。这个Z参考直接由当前测试结果生成，不是冻结的独立几何标定，不能把25/30当作固定标准的验证率。
- **23/30不代表新模型训练收益**：该比较用同一个rl8模型，代码和控制配置一起变了。四个原有模型的文件SHA256全部与本机相同；另新增ft_v6、ft_v8，但文档所称 `xy_policy_ftw_v14.pt` 未随包提供。
- **不能跨项目口径横比**：我们的36开发例基础20/36、45秒质量9/36；普通SAC最好24/36、质量0/36；最新小型CPU控制候选3/8、质量0/8，均与对方30例在初态、控制、信息、后端及验收上不同。不能合并或直接排名。

对方还明确记录历史28/30在当前串行IK下也无法复现。应学习他们保留这条负面证据的做法，不能引用28/30作为当前可用性能。

## 5. 新学习代码：可以借鉴数据设计，不宜整体迁入

有用新增：短时力/力矩历史 `ftw`、同状态脚本教师标签 `expert_dcmd`、训练阶段与实际模型调用阶段对齐、成功回合奖励、可选过滤随机探索。它们有助于减少单帧力的歧义，并明确模型在装配流程中负责哪一段。

但仍需修正：

- 默认动作标签是向后差分 `cmd[t]-cmd[t-1]`，却与当前状态、下一状态配成转移；应从真实记录时序确认 `s[t]→a[t]→s[t+1]`，不能把过去动作当未来决策。
- 标称IQL的Q目标仍使用 `Q_target(s_next, pi(s_next))`，不是标准IQL的 `V(s_next)`；不能按标准IQL直接解释结果。
- 成败标签只按文件basename汇总并取OR，不同数据目录同名回合可能串标签；数据重复和来源分组仍须独立去重。
- 过滤大动作后，仍把最后保留样本设为终止并附加全回合成败奖励；若裁去真正尾段，会把成功信号贴到较早状态。阶段筛选也要防止跨不连续时间段拼接转移。
- SFT可选力去皮，在线模型加载/输入未看到对应tare处理；训练与执行预处理必须一并冻结。
- `expert_dcmd` 是脚本XY误差项，不包含全部搜索和力项，既不是成熟最优专家，也不天然等于“专家动作减基础动作”的残差。行为克隆替代与残差叠加必须明确区分。
- 即便模型输入只有FT，控制状态机仍用物体真实位置决定落座、引导释放等；不能因此宣称整套系统已经只依赖可部署力觉。

依据：U/`train_offline_rl.py:28,75,104,216`；`fit_xy_model.py:56`；`controllers.py:56,707,909,1061`。

## 6. 与我们物理问题的关系

同事在其配置下只调控制就减振，是控制问题的支持证据，不能排除我们的独立接触异常。我们已在匹配设置的隔离冷接触中复现GPU深负分离点，CPU对应例首步为正分离；这些证据不依赖数采外环持续自激。另一方面CPU完整装配仍有释放漂移、质量未达标，也不能把所有失败归为GPU。

因此保留两条因果检查：接触有效性单独核验；控制在已明确的后端和固定物理参数下改进。CPU目前只是候选参考，不是已全面验证的物理真值。摩擦、材料阻尼、驱动阻尼和外环增益不是同一个参数；先固定真实任务摩擦进行控制开发，之后再做合理范围的鲁棒性验证。降低摩擦可以是机制诊断，却不能作为原任务成功率提升来汇报。

依据：`runs/autonomous_revision_20261104/实验计划修订.md:22` 及最新恢复实验记录。此前混用刚体原点与质心的残差分析已有更正，本文不沿用被撤销解释。
